# 金沢市デジ部 LP プロジェクト

このリポジトリは、金沢市職員によるデジタルコミュニティ「デジ部」のランディングページを管理します。`index.html` にサイト全体のマークアップとスタイルが含まれています。

## GitHub とつなぐためのかんたん手順

Git にあまり触れたことがない方でも迷わないよう、作業の流れをできるだけやさしい言葉でまとめました。実際の操作はインターネットにつながるご自身の PC で行ってください（この開発環境からは GitHub へアクセスできません）。

### 1. GitHub にリポジトリを用意する

- ブラウザで GitHub を開き、`kou-asanaga/dejibu` という名前でリポジトリを作成します。
- 作成時は **Public/Private** のどちらでもかまいません。後から変更もできます。

### 2. ローカルの Git にリモート（GitHub への行き先）を登録する
以下のコマンドをターミナルで実行します。コマンドは一行ずつ入力してください。

```bash
git remote add origin https://github.com/kou-asanaga/dejibu.git
```

> すでに `origin` が登録されている場合は、`git remote remove origin` で一度削除してからやり直してください。

登録できているか確認するには次のコマンドを実行します。

```bash
git remote -v
```

`origin  https://github.com/kou-asanaga/dejibu.git (fetch)` のように表示されれば成功です。

> **どうして必要なの？** `git push` は「どこへ送ればよいか」を知らないと動けません。`git remote add origin ...` はその送り先を教える作業です。登録しないまま push すると、「リモートが設定されていない」というエラーになります。

> **ブラウザから直接アップロードする方法もあります。** GitHub の Web 画面で `index.html` を手動アップロードすれば、ローカルでリモート登録しなくてもファイルを置くことは可能です。ただし、今後も継続して更新・同期する予定であれば、ローカルにリモートを設定して Git で push / pull できるようにしておく方が便利です。

### 3. GitHub の Web 画面から `index.html` を置く方法（ブラウザだけで完結）
ローカルで Git を設定しなくても、ブラウザから直接ファイルをアップロードできます。手順は以下のとおりです。

1. ブラウザで `https://github.com/kou-asanaga/dejibu` を開きます。
2. 画面右上の **Add file（ファイルを追加）** → **Upload files（ファイルをアップロード）** をクリックします。
3. 表示されたページに `index.html` をドラッグ＆ドロップするか、**choose your files** ボタンから選択します。
4. ページ下部の **Commit changes** ボタンでアップロードを確定します。

これで GitHub 上のリポジトリに `index.html` が追加されます。今後、同じ画面から更新版をアップロードすることもできます。

### 4. Pull リクエストを作って `index.html` を追加する方法（ブラウザ操作）
Pull リクエスト（PR）は「自分の変更をチームに見てもらい、OK ならメインに取り込んでもらうための相談窓口」です。いきなり本番に反映されないので、初心者でも安心して変更を提案できます。複数人で確認しながら進めたい場合はこちらの方法が便利です。

1. 手順「3. GitHub の Web 画面から `index.html` を置く方法」と同じように **Add file（ファイルを追加） → Upload files（ファイルをアップロード）** からファイルを選びます。
2. ページ下部の **Commit changes（変更をコミット）** セクションで、`Commit directly to the main branch`（メインブランチへ直接反映）の下にある **Create a new branch for this commit and start a pull request（新しいブランチを作成し、PR を開始）** を選びます。
3. 「ブランチ名（例: `add-index-html`）」「変更内容のメッセージ」を入力し、**Propose changes（変更を提案）** をクリックします。
4. 画面が切り替わったら、変更内容を確認し、**Create pull request（プルリクエストを作成）** を押すと PR が作成されます。
5. 作成した PR のページでは「何を変えたか」「どうして変えたか」をコメント欄で伝えると親切です。レビューしてくれる人との会話はここで行います。
6. PR がマージ（承認）されると、自動的にメインブランチへ反映されます。必要なら、マージ後に作成したブランチを削除してください。

> **ひと目で分かる PR の流れ**
> 1. 新しいブランチで `index.html` をアップロードする
> 2. 「Propose changes」で変更を提案する
> 3. 「Create pull request」で相談を開始する
> 4. レビューで OK が出たら「Merge」で反映される
>
> もしレビュー中に修正が必要になった場合は、同じブランチにファイルをアップロードし直すだけで PR に自動で変更が追加されます。

### 5. ローカルから GitHub にファイルをアップロードする（初回だけの操作）
ローカルで作業した内容を push したい場合は、どのブランチを送るか Git に伝えます。いま作業しているブランチが `work` の場合は、次のコマンドです。

```bash
git push -u origin work
```

以降は、`git push` と入力するだけで同じブランチにアップロードできます。

### 6. GitHub から変更を取り込む（pull する）
GitHub 上で誰かが更新したら、次のコマンドでローカルに取り込めます。

```bash
git pull
```

もし次のようなメッセージが出た場合は、まだ GitHub とのつながり（追跡ブランチ）が設定されていない可能性があります。

```
There is no tracking information for the current branch.
```

そのときはもう一度「5. ローカルから GitHub にファイルをアップロードする」のコマンドを実行して、GitHub とのつながりを設定し直してください。

> **重要:** この開発環境ではネットワーク制限により `git push` や `git pull` が失敗します。上記コマンドの練習はできますが、実際の通信はネットワークに接続された PC で行ってください。

## ランディングページの確認

ブラウザで `index.html` を開くと、デジ部の紹介ページをローカルで閲覧できます。
